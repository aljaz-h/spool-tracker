{% comment %} Below lg:, the inline search bar next to the logo is display:none (no room for it), so there was previously no way to search at all short of typing /search/?q= by hand. This toggles a full-width bar docked under the header instead of trying to cram a search icon's own popover/expand-in-place animation into the already-tight mobile header - simplest thing that reuses the exact same GET form/action as the desktop bar, just full-width. mobileSearchOpen lives on the root x-data in base.html, not scoped here, so the trigger button up in the left block and this panel can share it without a wrapping x-data of their own. Deliberately NOT x-show/x-cloak/x-transition (an earlier version of this used exactly that, plus a double requestAnimationFrame on the trigger's own focus() call to land after x-show's transition-deferred display flip) - it still took two taps on iOS Safari. iOS's rule for popping the keyboard is stricter than "focus() eventually lands on a focusable element": it has to happen synchronously inside the click handler with zero deferral, not even a single animation frame later, or the browser no longer credits it as a direct result of the tap. display:none and visibility:hidden both make an element unfocusable outright - which meant true synchronous focus() was never going to work while this panel used either for its closed state, no matter how the trigger called it. opacity + pointer-events (below), same as .spool-popover but without the visibility:hidden component .spool-popover itself relies on (compare app.css - that one's fine with being unfocusable while closed since it never needs to receive focus while hidden), keeps the input a genuinely normal, focusable DOM node at all times - just invisible and unclickable while closed. That's what makes the trigger's plain, undeferred $refs.mobileSearchInput.focus() actually work. Static opacity-0/pointer-events-none classes cover the instant before Alpine boots (no x-cloak needed, and none would work here anyway - it forces display:none); :class then swaps both tokens out for their open-state counterparts, it doesn't just append on top. {% endcomment %}
