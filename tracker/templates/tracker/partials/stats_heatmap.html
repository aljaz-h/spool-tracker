{% comment %} Fixed-size cells (not a fluid repeat(N, 1fr) grid) that scroll horizontally when they don't fit, same as GitHub's own contribution graph - a full year is ~52-53 week-columns, and squeezing all of them to fit a phone-width viewport left each column only a few px wide. CSS Grid's own repeat(N, 1fr) also gave 1fr tracks an implicit minmax(auto, 1fr) - a long month name's (whitespace-nowrap) intrinsic min-content width could force ITS label column wider than its 1fr share, throwing that grid out of alignment with the day-cell grid below it (same column count, but no comparable text forcing its own tracks wider) - confirmed live as exactly the "mushed together/ overlapping" glitch reported, not just a narrow-column clipping issue. Fixed pixel-width tracks on both grids sidesteps that entirely: every column is the same width on both grids, always, regardless of content. overflow-x-auto scroll-row lets the whole thing scroll on any viewport narrower than a full year's width, not just mobile - sm: and up usually has room to show it all without scrolling, this doesn't need its own breakpoint for that. {% endcomment %}
