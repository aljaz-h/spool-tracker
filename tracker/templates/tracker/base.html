{% load static %} {% block title %}Spool{% endblock %} {% comment %} iOS Safari doesn't act on the web manifest for "Add to Home Screen" - these are its own separate, older meta-tag convention for the same fullscreen/standalone install behavior the manifest already declares for every other browser. {% endcomment %} {% comment %} Alpine plugins register via a document-level "alpine:init" listener that must be attached before Alpine's own core dispatches it - defer scripts execute in document order, so this only works with the plugin's {% comment %} x-effect below locks background scroll for as long as the bottom sheet is open, toggling Tailwind's own overflow-hidden on (not $el - this div isn't the scrolling element, is). Without it, dragging the sheet down (its own touchmove handler in bottom_sheet.html) also dragged the page behind it, since nothing told the browser this gesture wasn't an ordinary scroll. Deliberately scoped to bottomSheetOpen alone, not sidebarOpen/mobileSearchOpen too - an earlier version locked for all three "since it's the same bug class", but neither of those two was ever actually reported as scrolling the background, and that wider scope turned out to cause a real, separate bug on iOS Safari: opening then closing the mobile search bar left the bottom nav's own position:fixed visibly desynced from the page during the next scroll (drifting partway up, snapping back on scroll-up) until something else forced a fresh layout pass. Toggling overflow-hidden on is a known trigger for iOS Safari mishandling fixed-position descendants while its dynamic toolbar is also moving - not worth paying that cost anywhere it wasn't actually needed. {% endcomment %}
